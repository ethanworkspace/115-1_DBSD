### 看懂一張表

**Table（資料表）** — 資料庫裡的一張表格，同一類東西放同一張，直的欄位先定好，橫的資料可以一直加。  
　　*例*：本課的 ships 表固定 7 個欄位 id、ship_name、imo、ship_type、gross_tonnage、build_year、country_id，目前裝了 50 艘船。  
　　*易混*：Table ≠ Database。資料庫像資料夾，資料表是裡面的一份表格，一個 maritime 資料庫可以同時有 ships 和 voyages 兩張表。

**Record (Row)（紀錄、列）** — 表格裡橫的一整條，代表一個具體的東西。  
　　*例*：「長榮貨輪、IMO 9811000、貨櫃船、20,388 噸、2018 年」這一整條就是一筆 record，50 艘船就是 50 列。  
　　*易混*：Record ≠ Field。一列是一艘船的全部資料，一欄是全部 50 艘船的同一個屬性。

**Field (Column)（欄位、行）** — 表格裡直的一整行，代表同一種屬性，整行只能放同一種資料。  
　　*例*：gross_tonnage 這一欄裝著 50 個總噸位數字，不能有一格改填「不詳」兩個字。  
　　*易混*：欄位名 ≠ 欄位值。ship_type 是欄位名，「貨櫃船」是其中一格的值；值忘了加引號寫成 WHERE ship_type = 貨櫃船，MySQL 會把它當成另一個欄位名而回報 Unknown column。

**Data Type（資料型別）** — 事先規定某一欄只准放哪一種資料，放錯時資料庫會擋下來或自己動手改掉。  
　　*例*：build_year 用 INT 存 2018、ship_name 用 VARCHAR(50)；把「20,388」連逗號一起塞進 INT 的 gross_tonnage，XAMPP 預設的嚴格模式會直接報錯擋下整筆，非嚴格模式才會只收下逗號前的 20。  
　　*易混*：INT ≠ VARCHAR。年份若用 VARCHAR 存，排序會按字串一個字一個字比，'999' 會排在 '2018' 後面。

**NULL（空值）** — 代表這一格根本沒有填值，它不是 0，也不是空白字串。  
　　*例*：50 艘船有 3 艘查不到建造年，那 3 格是 NULL；COUNT(build_year) 只會回 47，COUNT(*) 才是 50。  
　　*易混*：= NULL ≠ IS NULL。寫 WHERE build_year = NULL 一筆都查不到，必須寫 IS NULL 才抓得出那 3 筆。

### 資料庫設計與正規化

**ER Diagram（實體關聯圖）** — 動手建表之前，先用方塊和連線畫出有哪些東西、它們之間怎麼互相牽連的設計草圖。  
　　*例*：畫 ships 與 voyages 兩個方塊，中間拉一條「一艘船有多個航次」的線，50 艘船對應 120 筆航次，之後照圖建兩張表。  
　　*易混*：ER 圖 ≠ 建表清單。圖上若畫成「一艘船停過多個港口、一個港口也停過多艘船」，不能只建船舶和港口兩張表，還要再開第三張表專門記哪艘船停過哪個港。

**Primary Key（主鍵）** — 每一列的身分證號，同一張表裡不會重複也不能空白，用它就能精準指到唯一一列。  
　　*例*：ships 用 id 當主鍵，50 艘船拿到 1 到 50 共 50 個不重複的編號；再硬插一筆 id = 7 的船，MySQL 會以 Duplicate entry 拒絕。  
　　*易混*：主鍵 ≠ 隨便挑一欄來用。ship_name 會同名也會改名，改一次船名就對不回原來的航次，所以永遠不能當主鍵；id 排在第一欄只是習慣，關鍵是它保證不重複也不為空。

**Foreign Key（外鍵）** — 一張表裡用來指向另一張表某一列身分證號的欄位，代表這兩筆資料是同一件事的兩半。  
　　*例*：voyages 的 ship_id 指向 ships 的主鍵；想存一筆 ship_id = 999 的航次會失敗，因為 50 艘船的編號只到 50。  
　　*易混*：主鍵 ≠ 外鍵。主鍵回答「我是誰」且不可重複，外鍵回答「我屬於誰」，同一個 ship_id 可以出現在 12 筆航次裡。

**Normalization（正規化）** — 把一張塞滿重複內容的大表，依規則拆成幾張小表，讓同一件事只被寫下一次。  
　　*例*：原本 50 列裡「巴拿馬」這個船籍國被寫了 18 次，拆出 countries 表後只存 1 次，ships 改存 country_id。  
　　*易混*：正規化 ≠ 拆得越碎越好。每拆出一張表，之後查詢就要多把表接回來一次，本課做到第三正規化就停。

**1NF（第一正規化）** — 每一格只能放一個值，不可以在一格裡塞一串清單。  
　　*例*：某艘船靠過「高雄、台中、基隆」不能全擠進 port 一格，要拆成 3 筆航次紀錄。  
　　*易混*：1NF ≠ 把一格拆成三欄。port1、port2、port3 每格雖然只有一個值，但這叫重複群組，一樣不合 1NF，而且第四個港口一來就得改表結構，正解是另開航次表。

**2NF（第二正規化）** — 在每格一值的前提下，如果主鍵是兩個欄位合起來的，就不准有欄位只靠其中一個欄位就決定。  
　　*例*：voyages 用 ship_id 加 voyage_no 當主鍵，卻放了只看 ship_id 就能決定的 ship_name，這就違反 2NF，船名要搬回 ships。  
　　*易混*：2NF ≠ 3NF。2NF 只管「只依賴主鍵的一半」，當主鍵只有單一欄位時自動就符合 2NF。

**3NF（第三正規化）** — 除了主鍵以外，其他欄位之間不可以互相決定，每個欄位都要直接由主鍵決定。  
　　*例*：ships 同時放 country_id 和 country_name 時，國名是被國碼決定而不是被主鍵 id 決定，違反 3NF，國名要移到 countries 表。  
　　*易混*：3NF ≠ 現在有沒有重複資料。就算這 50 筆剛好沒矛盾，只要有「非主鍵決定非主鍵」，改一次國名就會漏改。

### SQL 查詢

**SQL（結構化查詢語言）** — 跟資料庫溝通的專用語言，你只描述要什麼，怎麼找由資料庫自己決定。  
　　*例*：想知道 50 艘船裡哪些超過 20,000 噸，寫一句 SELECT … WHERE gross_tonnage > 20000 就回 16 筆，不必自己寫迴圈逐筆比。  
　　*易混*：SQL ≠ MySQL。SQL 是語言，MySQL 是聽得懂這個語言的那套軟體。

**SELECT（查詢）** — 把表裡你要的欄位和列撈出來看，原始資料不會被動到。  
　　*例*：SELECT ship_name, gross_tonnage FROM ships; 回傳 50 列乘以 2 欄。  
　　*易混*：SELECT * ≠ 比較方便就該用。星號會把 7 個欄位全拉出來，只要 2 欄時是白白多搬資料。

**WHERE（篩選條件）** — 加在查詢裡的條件，只留下符合條件的那幾列。  
　　*例*：WHERE ship_type = '貨櫃船' AND build_year >= 2015 把 50 筆篩成 12 筆。  
　　*易混*：WHERE ≠ HAVING。WHERE 在分組前篩單一列，HAVING 在分組後篩整組的統計結果。

**GROUP BY（分組統計）** — 把列依某一欄分堆，每一堆用 COUNT、AVG 這類函數算出一個數字。  
　　*例*：GROUP BY ship_type 把 50 筆分成 4 堆，COUNT(*) 回傳 4 列：貨櫃船 21、散裝船 15、油輪 9、其他 5。  
　　*易混*：GROUP BY ≠ ORDER BY。GROUP BY 把 50 列壓成 4 列統計值，ORDER BY 出來仍然是 50 列，只是換個順序。

**JOIN（資料表連接）** — 把兩張表用共同的欄位對起來，讓同一列同時看到兩邊的資料。  
　　*例*：ships JOIN voyages ON ships.id = voyages.ship_id 回傳 120 列，每一列都同時帶著船名和該筆航次。  
　　*易混*：JOIN ≠ UNION。JOIN 是橫向把欄位加寬，UNION 才是縱向把兩份結果疊起來。

**LEFT JOIN（左外部連接）** — 以左邊那張表為主，左邊每一列都保留，右邊找不到對應就補空值。  
　　*例*：ships LEFT JOIN voyages 回 126 列，也就是 120 筆航次加上 6 艘從未出航的船，那 6 列的航次欄位是 NULL；改成 JOIN 就只剩 120 列。  
　　*易混*：LEFT JOIN ≠ JOIN。要找「一次航次都沒有的船」只能用 LEFT JOIN 再加 IS NULL，內部連接永遠查不到它們。

### PHP 存取資料庫

**$_POST / $_GET（表單傳來的資料）** — PHP 內建用來接住使用者從網頁表單送過來的值的變數。  
　　*例*：查詢表單選「油輪」送出後，PHP 用 $_POST['ship_type'] 拿到這個字串，再拿去查那 9 筆。  
　　*易混*：$_POST ≠ $_GET。GET 的值整串出現在網址列也留在瀏覽紀錄裡，所以密碼要走 POST；但 POST 只是不顯示，內容一樣沒有加密，要靠 HTTPS。

**PDO（PHP 資料物件）** — PHP 內建的一套統一連線工具，用它連資料庫，日後換成別套資料庫時程式改動最少。  
　　*例*：new PDO('mysql:host=localhost;dbname=maritime;charset=utf8mb4', 'root', '') 連上之後，才能對那 50 筆下 SQL。  
　　*易混*：PDO ≠ SQL。PDO 只是送信的郵差，信的內容仍然是你自己寫的 SQL。

**fetch / fetchAll（取回結果）** — SQL 送出去之後還要再做這個動作，資料才會真的被搬進 PHP 的變數裡。  
　　*例*：fetchAll() 一次把 50 筆變成一個陣列；fetch() 一次只拿一筆，要放在 while 迴圈裡跑 50 次。  
　　*易混*：execute() 成功 ≠ 拿到資料。沒有 fetch，變數就是空的，畫面自然什麼都不顯示。

**Session（連線狀態）** — 伺服器替每位使用者保管的暫存空間，用來記住你是誰、登入了沒，換頁也不會忘。  
　　*例*：登入成功後寫 $_SESSION['user'] = 'C110123456'，之後每一頁開頭檢查這格有沒有值，沒有就踢回登入頁。  
　　*易混*：Session ≠ Cookie。真正的資料放在伺服器上，瀏覽器手上只有一組辨識用的編號。

**Exception（例外）** — 程式跑到一半出狀況時丟出來的錯誤包裹，可以被接住處理，而不是整頁掛掉。  
　　*例*：MySQL 沒啟動時 PDO 會丟出 PDOException，用 try/catch 接住就顯示「資料庫連線失敗」，而不是把含帳號密碼的錯誤訊息噴滿畫面。  
　　*易混*：Exception ≠ 語法錯誤。語法錯誤在執行前就過不了，例外是跑起來之後才發生，而且抓得住。

### 安全防護

**SQL Injection（SQL 注入）** — 使用者在輸入框裡填的不是資料而是 SQL 片段，害你的程式把它當成指令去執行。  
　　*例*：在自己電腦的 XAMPP 上測自己寫的登入頁，帳號欄填 ' OR '1'='1' -- ，拼接出來的條件永遠成立，不用密碼就登入成功。  
　　*易混*：注入 ≠ 猜中密碼。它不是猜對了，而是整句判斷被改寫，密碼那一段根本沒有被比對。

**Prepared Statement（預備語句）** — 先把 SQL 的骨架定下來交給資料庫，使用者輸入只能當成一個值填進預留的問號，指令歸指令、資料歸資料。  
　　*例*：prepare("SELECT * FROM users WHERE account = ?") 之後 execute(["' OR '1'='1"])，那串字會被當成一個不存在的帳號，結果 0 筆。  
　　*易混*：預備語句 ≠ 把危險字元濾掉。它不是先把引號洗乾淨，而是使用者打的字從頭到尾都不會被當成 SQL 指令看；自己拼字串再想辦法把引號換掉，總會有漏網的寫法。

### 測試與驗證

**Acceptance Criteria（驗收條件）** — 動手寫之前先寫死「做到什麼程度才算完成」，而且要能用一次操作判定對或錯。  
　　*例*：「輸入貨櫃船應回傳 21 筆，且每一筆的 ship_type 都等於貨櫃船」，跑完對得上才算完成。  
　　*易混*：驗收條件 ≠ 功能描述。「可以查詢船種」無法判定對錯，「回傳 21 筆」才驗得起來。

**Assertion（斷言）** — 在程式裡寫下一行「這裡必須成立」，一旦不成立就馬上喊出來。  
　　*例*：查完貨櫃船後寫 assert(count($rows) === 21)，哪天資料被改成 20 筆，程式自己會報錯，不必人盯著看。  
　　*易混*：assert ≠ echo。echo 要靠人用眼睛比對，assert 由程式直接判定通過或失敗。

**Boundary Value（邊界值）** — 專挑條件的臨界點來測，因為錯誤幾乎都發生在「剛好等於」那一格。  
　　*例*：規格說「20,000 噸以上算大型船」，條件寫 > 20000 查到 16 筆、寫 >= 20000 查到 17 筆，差的就是剛好 20,000 噸那一艘，所以 19,999、20,000、20,001 三個值都要測。  
　　*易混*：邊界值 ≠ 極端值。最大最小只是其中一種，真正的邊界是條件本身的分界點。

**Equivalence Class（等價類）** — 把輸入分成幾群預期反應一樣的，每群挑一個來測就夠，不必每個值都試。  
　　*例*：build_year 分成合法年份 2018、未來年份 2030、非數字 abc 三群各測一次，而不是把 50 個年份全部輸入一遍。  
　　*易混*：等價類 ≠ 偷懶少測。分錯群才會漏測；分對群之後，同一群多測十次也不會多抓到錯。

**Data Integrity Test（資料完整性測試）** — 用查詢去檢查資料庫裡的資料有沒有違反當初講好的規則。  
　　*例*：把 50 筆船舶和 120 筆航次匯入之後跑 SELECT COUNT(*) FROM voyages WHERE ship_id NOT IN (SELECT id FROM ships)，答案必須是 0，不是 0 就有指向不存在船舶的孤兒航次。  
　　*易混*：完整性 ≠ 正確性。它保證沒有孤兒和重複，但不保證那 50 個噸位數字真的抄對。

**Integration Test（整合測試）** — 把表單、PHP、資料庫整條路串起來，從使用者的角度走一遍。  
　　*例*：用 curl 打 http://localhost/api/ships.php?type=油輪，檢查回傳的資料是 9 筆而且狀態碼是 200。  
　　*易混*：整合測試 ≠ 單句 SQL 測得過就好。同一句查詢在 phpMyAdmin 回 9 筆，換成網頁送出卻可能因為參數名打錯或編碼不同而回 0 筆，整條路走一遍才算數。

### API 與資料交換

**JSON（物件表示法資料格式）** — 一種用大括號和冒號寫成的純文字資料格式，人看得懂，程式也好解析。  
　　*例*：把 9 筆油輪用 json_encode 輸出，前端 JavaScript 收到後直接用 data[0].ship_name 取出船名。  
　　*易混*：JSON ≠ JavaScript 物件。JSON 本質是一串字串，要先解析過才能當物件操作。

**AJAX（非同步網頁更新）** — 網頁不整頁重新載入，就在背景跟伺服器要資料，再只更新畫面的一小塊。  
　　*例*：下拉選單從貨櫃船改成油輪時，背景要一次資料就把表格從 21 列換成 9 列，網址不變、畫面不閃。  
　　*易混*：AJAX ≠ 一種新語言。它是既有的 JavaScript 加上背景送出的請求所組成的做法。

**REST API (Endpoint)（資料介面與端點）** — 伺服器開放的一個固定網址，照約定送請求給它，它回給你資料而不是網頁。  
　　*例*：GET /api/ships.php?type=油輪 回傳 9 筆 JSON，同一支程式可以同時給網頁和手機 App 使用。  
　　*易混*：API ≠ 網頁。API 回的是資料，用瀏覽器直接開會看到一堆括號和引號，那是正常的。

**HTTP Status Code（HTTP 狀態碼）** — 伺服器回應時附上的三位數號碼，表示這次請求是成功還是哪一種失敗。  
　　*例*：查到 0 筆仍然回 200，代表請求成功但結果是空的；網址打錯回 404；PHP 出錯回 500。  
　　*易混*：200 ≠ 結果正確。200 只代表請求有被處理完，內容仍可能是錯的，測試要另外比對筆數。

### 進階主題：跨章節綜合

**Index（索引）** — 幫某個欄位另外建一份排好序的對照表，讓資料庫不必從頭翻就能直接跳到目標那一列。  
　　*例*：為了看出差別，另外灌進 50,000 筆彼此不重複的測試船舶；用 imo 查一艘船原本要從頭翻完 50,000 列，對 imo 建索引後只要讀 1 列。  
　　*易混*：索引 ≠ 越多越好。每多一個索引，之後每次新增資料都要多維護一份，寫入變慢也更佔空間。

**EXPLAIN（執行計畫）** — 在查詢前面加上這個字，資料庫會先告訴你它打算怎麼找，而不是真的把結果跑出來。  
　　*例*：EXPLAIN SELECT * FROM ships WHERE imo = '9811000' 顯示 type=ALL、rows=50，代表整張表都要翻；對 imo 建索引後變成 type=ref、rows=1。  
　　*易混*：EXPLAIN ≠ 計時。它給的是執行計畫和預估要掃幾列，不是真正花了幾毫秒。

**Transaction（交易）** — 把好幾個動作綁成一包，要嘛全部成功，要嘛全部退回原狀，不會做到一半卡住。  
　　*例*：新增一筆航次並同時把該船狀態改成航行中，若第二步失敗就 ROLLBACK，資料回到 120 筆航次的樣子，不會多出一筆孤兒。  
　　*易混*：交易 ≠ 備份還原。ROLLBACK 只能退回這一包還沒 COMMIT 的動作，已經 COMMIT 的資料救不回來。

**N+1 Query（N 加 1 查詢問題）** — 先查一次拿到清單，再對清單裡每一筆各查一次，查詢次數就跟資料筆數一樣多。  
　　*例*：先撈 50 艘船，再在 PHP 迴圈裡每艘查一次航次，總共送出 51 次查詢；改成一句 JOIN 只要 1 次。  
　　*易混*：慢 ≠ SQL 寫得爛。每一句單獨看都很快，問題出在它被呼叫了 50 次，只看單句的執行計畫完全看不出來。

**Load Testing (ApacheBench)（壓力測試）** — 用工具在短時間內灌進大量請求，看服務撐不撐得住、每個請求要等多久。  
　　*例*：ab -n 200 -c 10 對查詢頁送出 200 次請求、同時 10 條連線，記錄每秒完成數與平均回應時間，建索引前後各測一次做比較。  
　　*易混*：壓力測試 ≠ 功能測試。它量的是撐不撐得住，回應再快也不代表那 9 筆資料是對的。

</details>

## GitHub 基本操作（新手看這裡）

> 每週作業以 Canva 繳交；**期末專案以小組 GitHub repo 繳交**，請務必熟悉以下操作。組長建立 repo 後，把組員與老師 `pychang-ai` 加為 collaborator。

### 一、第一次設定（只做一次）

1. 到 <https://github.com> 註冊 GitHub 帳號。
2. 安裝 Git：<https://git-scm.com/download/win>（Windows）。
3. 打開 VS Code 終端機或命令提示字元，設定你的名字與 Email（要跟 GitHub 帳號一致）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的GitHub註冊Email"
```

### 二、取得課程 / 專案 repo（複製到自己電腦）

```bash
git clone https://github.com/帳號/repo名稱.git
cd repo名稱
```

### 三、交作業或存檔的三步驟：add → commit → push

```bash
git add .                      # 把這次的變更加入暫存區（. 代表全部檔案）
git commit -m "完成第10週作業"  # 把暫存區的變更存成一個版本，-m 後面寫這次做了什麼
git push                       # 把本機的版本上傳到 GitHub
```

> 口訣：**add 收東西 → commit 存檔（要寫說明）→ push 上傳**。三步驟每次都一樣。

### 四、常用查看指令

| 指令 | 作用 |
|------|------|
| `git status` | 看目前有哪些檔案改了、加了、還沒 commit（最常用，動手前先打這個） |
| `git log --oneline -5` | 看最近 5 個版本；`HEAD -> main` 那一行就是你**現在所在的位置** |
| `git rev-parse --short HEAD` | 只印出目前 HEAD 的版本代號（7 碼） |
| `git branch` | 看目前在哪個分支（前面有 `*` 的就是目前所在） |
| `git diff` | 看改了哪些內容（還沒 add 的部分） |
| `git pull` | 把 GitHub 上別人（或老師）的最新版本拉下來 |

> **HEAD 是什麼**：HEAD 就是「你現在站在哪一個版本上」的指標。打 `git status` 會看到 `On branch main`（在哪個分支），打 `git log --oneline -5` 會看到 `(HEAD -> main)` 標在最新版本上——那就是 HEAD 現在的位置。
