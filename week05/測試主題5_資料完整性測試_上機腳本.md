## 這一節在做什麼

本課程主軸是人工智慧 artificial intelligence（AI）時代的軟體測試與驗證。AI 工具可以在三秒內
產生一段建表語法與一段查詢，語法也會通過，但「這張表到底有沒有被保護」「這個答案到底對不對」
不會寫在它的回答裡。唯一的確認方式有兩個：故意做壞事看資料庫擋不擋，以及把規格寫成一句
答案只有通過或不通過的查詢。

這一節先做第二件事，再做第一件事。順序是刻意的：**先有可判定的驗收條件，才有資格說測試通過**。
這是第 4 週【測試主題 1】規格變成驗收條件的延伸，也是第 6 週驗收 1 的縮小版預演。

## 規則一　所有破壞只在複本上做，不准動 ships

你手上的 ships 是今天作業 W05 要用的資料。如果在 ships 上塞一筆重複的編號而資料庫沒有擋你，
你的作業答案就會多算一筆，而畫面是綠色的，你不會發現。

所以這一節的硬規則是：**先複製一張 ships_chk，所有違規語句都打在 ships_chk 上**，ships 全程不動。

## 步驟 1　建立複本，2 分鐘

用 phpMyAdmin 的畫面操作，不要用 SQL。

1. 左側點 ships → 上方「操作」頁 → 「複製資料表」
2. 新名稱填 `ships_chk`
3. **選「結構與資料」，不要選「僅資料」**
4. 按執行，左側應出現 ships_chk

```sql
SELECT COUNT(*) FROM ships_chk;
```

必須回 **50**。三個版本都是 50 列，這個數字和你拿到哪一版無關。

第 3 點很重要。只複製資料不複製結構，主鍵 primary key（PK）不會跟著過來，後面步驟 3 就看不到
資料庫擋你，整節課的重點會消失。

## 步驟 2　先寫驗收條件，六句，4 分鐘

這六句就是 ships 這張表的規格。每一句的答案只有一個，對不上就是不通過，不需要問任何人。
先在資料還乾淨的時候跑一次，把答案抄下來當基線。

```sql
-- 驗收 1　列數
SELECT COUNT(*) AS 列數 FROM ships_chk;

-- 驗收 2　編號不重複：相異的編號個數必須等於列數
SELECT COUNT(DISTINCT ship_id) AS 相異編號 FROM ships_chk;

-- 驗收 3　把重複的編號直接抓出來
SELECT ship_id, COUNT(*) AS 次數 FROM ships_chk
GROUP BY ship_id HAVING COUNT(*) > 1 ORDER BY ship_id;

-- 驗收 4　船型到底有哪幾種，先列出來，把結果抄在下面的表格裡
SELECT DISTINCT `船型` FROM ships_chk ORDER BY `船型`;

-- 驗收 5　船型只能是驗收 4 列出來的那幾種。把驗收 4 的結果自己填進括號裡
SELECT COUNT(*) AS 不合規 FROM ships_chk
WHERE `船型` NOT IN ('______', '______', '______');

-- 驗收 6　數值必須落在合理範圍
SELECT COUNT(*) AS 超出範圍 FROM ships_chk
WHERE `噸位_千噸` NOT BETWEEN 1 AND 500
   OR `靠泊時間_小時` NOT BETWEEN 1 AND 100;
```

| 驗收 | 我跑出來的答案 | 必須是 | 不是這個答案代表什麼 |
|---|---|---|---|
| 1 列數 | | **50** | 匯入掉列或多塞了列 |
| 2 相異編號 | | **50** | 有編號重複，與驗收 1 的差額就是重複的筆數 |
| 3 重複編號 | | **0 列** | 列出來的就是重複的編號與次數 |
| 4 船型清單 | | 自己跑、自己抄 | 之後每次重跑都必須和第一次一樣 |
| 5 不合規 | | **0** | 有列的船型不在你自己列出來的清單裡 |
| 6 超出範圍 | | **0** | 噸位或靠泊時間是負數、0 或離譜的大數 |

驗收 4 與驗收 5 是一組：**先用資料本身告訴你合法值有哪些，再用那份清單回頭檢查資料**。

這裡要記一句話：六句全過，不代表資料是對的，只代表它沒有違反我們寫下來的這六條規格。
規格沒寫到的錯，查詢抓不出來。這是驗收條件的能力上限。

## 步驟 3　故意製造重複主鍵，再用驗收條件抓它，5 分鐘

ship_id = 1 在你的資料裡一定存在，所以下面這句一定是重複。**打在 ships_chk 上，不要打在 ships 上**。

```sql
INSERT INTO ships_chk (ship_id, `船型`, `噸位_千噸`, `靠泊時間_小時`)
VALUES (1, '貨櫃', 99.9, 25.0);
```

兩種結果都要處理，而且兩種都有收穫。

| 畫面出現 | 代表什麼 | 接下來做什麼 |
|---|---|---|
| 紅色錯誤，編號 1062，內容是 Duplicate entry | 主鍵約束生效了。主鍵的兩個條件是不重複與不為空，這一句踩的是第一個 | 把錯誤號碼與英文原文抄進記錄表，寫「通過」 |
| 綠色成功，1 row inserted | 這張複本沒有主鍵。步驟 1 第 3 點選錯了 | 寫「未通過」，接著照樣做下面的重跑 |

不論擋下來或沒擋下來，**六句驗收條件都要重跑一次**，這是這一節真正要練的動作。

| 驗收 | 塞進去之後 | 說明 |
|---|---|---|
| 1 列數 | 51 | 多了一列 |
| 2 相異編號 | 50 | 沒變，與驗收 1 差 1，差額就是重複筆數 |
| 3 重複編號 | 1 列，ship_id = 1，次數 2 | 直接指出是哪一筆 |
| 4 船型清單 | 沒變 | 新塞的那筆是貨櫃，清單裡本來就有 |
| 5 不合規 | 0，沒變 | 同上 |
| 6 超出範圍 | 0，沒變 | 噸位 99.9 與靠泊 25.0 都在範圍內 |

這張表就是今天最重要的一句話：**驗收 4、5、6 全過，資料仍然是壞的**。
只看有沒有紅字，或只跑一部分檢查，就會漏掉這種錯。

還原，並確認回到基線：

```sql
DELETE FROM ships_chk WHERE ship_id = 1 AND `噸位_千噸` = 99.9;
SELECT COUNT(*) AS 列數 FROM ships_chk;
```

第二句必須回到 **50**。DELETE 後面的 `AND 噸位_千噸 = 99.9` 不可以省略，否則你會把原本那一筆
ship_id = 1 一起刪掉，列數變成 49。

## 步驟 4　教師前台示範，8 分鐘

這一段**老師在前面做，你不用動手**，也不會列入小考與期中考。你要做的是在記錄表上寫三欄：
看到的錯誤號碼、它擋住了什麼、如果沒擋住會發生什麼。

| 示範 | 老師送出的違規 | 你要記下的重點 |
|---|---|---|
| 非空約束 NOT NULL | 把船型這一格留空 | 錯誤號碼。擋的是「這一格沒有值」，不是「值不合理」。空值 NULL 的意思是不知道，不等於 0 也不等於空字串 |
| 外來鍵 foreign key（FK）擋新增 | 在靠泊紀錄表塞一筆指向不存在的船 | 錯誤號碼。外鍵保證每一筆紀錄都掛在真的存在的船上 |
| 外來鍵擋刪除 | 刪掉一艘已經有靠泊紀錄的船 | 錯誤號碼。外鍵是雙向保護，既不准你新增孤兒，也不准你製造孤兒 |
| 語法有寫不等於約束生效 | 同一段建表語法換一個儲存引擎再跑一次 | 語法完全不報錯，外鍵卻完全不存在 |

最後一列是這一段的重點。AI 寫得出 `FOREIGN KEY`，資料庫也收下了，但換一個儲存引擎它就只是
一行註解。**語法通過不等於約束生效，只能實測。**

記錄表上抄的要是螢幕上真正出現的字，不是上面這張表裡的字。錯誤訊息的文字會隨資料庫版本不同。

## 步驟 5　清理與確認，3 分鐘

```sql
SELECT COUNT(*) AS 列數 FROM ships;
```

必須是 **50**。ships 全程沒有被動過，所以這一句一定對；跑它的目的是養成
「動完手一定要回頭確認本體沒事」的習慣。

確認之後，在 phpMyAdmin 左側進 ships_chk 的「操作」頁刪除這張複本。**ships 不要刪。**
