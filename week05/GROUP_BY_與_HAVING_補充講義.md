## 一、GROUP BY 在做什麼：把 50 列折成幾列

```sql
SELECT `船型`, COUNT(*) AS 筆數
FROM ships
GROUP BY `船型`
ORDER BY `船型`;
```

GROUP BY 的動作是「把指定欄位值相同的列收成一堆，每一堆只輸出一列」。
聚合函數算的是每一堆自己的數字，不再是整張表的數字。

| 船型 | 筆數 |
|---|---|
| | |
| | |
| | |

自我檢查：**所有筆數相加必須等於 50**。GROUP BY 不會漏掉任何一列，也不會把同一列算進兩堆。
加不回 50 就表示你的表不是 50 列，回去跑 `SELECT COUNT(*) FROM ships;`。

另外請一定要寫 ORDER BY。GROUP BY 本身不保證輸出的順序，舊版資料庫剛好會順便排序，
新版不會，所以同一句在不同電腦上列的先後可能不同。

## 二、GROUP BY 與 ORDER BY 的差別：幾列與 50 列

兩者都寫在 SELECT 的後半段，長得很像，做的事完全不同。

| | ORDER BY | GROUP BY |
|---|---|---|
| 做什麼 | 把列重新排先後 | 把列併成堆 |
| 回傳幾列 | **還是 50 列**，一列都沒少 | **每一堆一列**，比 50 少很多 |
| 看得到個別船嗎 | 看得到，ship_id 還在 | 看不到，被併進堆裡了 |
| 什麼時候用 | 想知道「最久的是哪一艘」 | 想知道「哪一種船型平均比較久」 |

``SELECT * FROM ships ORDER BY `靠泊時間_小時` DESC;`` 回 50 列，
``SELECT `船型`, COUNT(*) FROM ships GROUP BY `船型`;`` 回幾列，自己跑出來看。

## 三、WHERE 與 HAVING 的差別：分組前篩列，分組後篩組

一句 SELECT 的執行順序是：FROM → WHERE → GROUP BY → 算聚合函數 → HAVING → ORDER BY → LIMIT。
WHERE 在分組之前，所以它篩掉的是「列」；HAVING 在分組與聚合之後，所以它篩掉的是「整堆」。

```sql
-- WHERE：先丟掉靠泊 20 小時以下的列，剩下的才拿去分組
SELECT `船型`, COUNT(*) AS 筆數 FROM ships
WHERE `靠泊時間_小時` > 20
GROUP BY `船型` ORDER BY `船型`;

-- HAVING：50 列全部拿去分組，算完平均後再丟掉平均不到 21 小時的那一整堆
SELECT `船型`, ROUND(AVG(`靠泊時間_小時`), 2) AS 平均靠泊 FROM ships
GROUP BY `船型` HAVING AVG(`靠泊時間_小時`) > 21 ORDER BY `船型`;
```

兩句的差別用結果最好懂：WHERE 那句每一種船型都還在，只是筆數變小；
HAVING 那句的列數會比第一節少，少掉的是哪一種、為什麼少，由你自己跑出來後回答。

聚合條件不能寫進 WHERE。`WHERE COUNT(*) > 10` 會得到
`#1111 - Invalid use of group function`，因為 WHERE 執行的時候 COUNT 還沒算出來。
口訣是：條件裡有 COUNT、AVG、SUM、MAX、MIN 就得用 HAVING，沒有就用 WHERE。

## 四、三句可以直接在自己資料上跑的指令

```sql
-- Q1
SELECT `船型`, COUNT(*) AS 筆數 FROM ships GROUP BY `船型` ORDER BY `船型`;

-- Q2

-- Q3
SELECT `船型`, ROUND(AVG(`靠泊時間_小時`), 2) AS 平均靠泊
FROM ships GROUP BY `船型` HAVING AVG(`靠泊時間_小時`) > 21 ORDER BY `船型`;
```

|---|---|---|---|
| Q1 | | | 筆數相加必須等於 50 |
| Q2 | | | 筆數欄必須和 Q1 完全一樣 |

Q3 的平均值和 Q2 一樣，是因為 **HAVING 不會改變算出來的值，只決定那一列要不要留**。
如果你的 Q3 平均值和 Q2 對不上，那是你其中一句打錯了，不是 HAVING 的問題。

不寫 ROUND 的話畫面上會出現像 19.333333333333332 這種一長串的數字，那不是算錯，
是小數在電腦裡的存法，用 ROUND 取兩位就好。

## 五、和投影片第 37 頁的對照，順便驗證自己的作業

投影片第 37 頁的做法是用 WHERE 把範圍縮到一個對象再 COUNT，想知道每一種船型就得跑好幾句。
GROUP BY 一句就把全部答案一起給你。兩邊答案必須相同，不同就是其中一邊寫錯了。

```sql
-- 投影片的做法，一種船型跑一次
SELECT COUNT(*) FROM ships WHERE `靠泊時間_小時` > 20 AND `船型` = '貨櫃';
-- 本頁的做法，跑一次
SELECT `船型`, COUNT(*) FROM ships WHERE `靠泊時間_小時` > 20 GROUP BY `船型` ORDER BY `船型`;
```

| 船型，自己填 | 筆數 |
|---|---|
| | |
| | |
| | |
| **相加** | |
| 全表 `靠泊時間_小時` > 20 的筆數 | |

**最後兩列必須相等。** 相加之後對不上，就是其中一句寫錯了，不必問任何人就知道要重做。
再多一個檢查：各船型筆數相加不可能大於全表 50 筆。

**注意**：這張表裡「貨櫃」那一格，就是今天作業 W05 要你算的那個數字。
作業只需要 WHERE 加 COUNT 一句，不必用 GROUP BY。
作業要你寫的是「和我自己數的一樣／不一樣」，所以**請先用 phpMyAdmin 的瀏覽頁或 Excel
自己數一次**，再用上面這句 GROUP BY 對照。先看答案再去數，等於沒有驗證。

## 六、三個一定會踩到的錯

1. **SELECT 裡放了沒分組的欄位**。例如 ``SELECT `船型`, ship_id, COUNT(*) FROM ships GROUP BY `船型`;``
   一個船型是一整堆船，一堆船沒有「那一個」ship_id，所以這句問的是一個不存在的東西。
   在我們教室的環境下，資料庫**不會報錯**，它會從那一堆裡安靜地挑一個 ship_id 給你，
   而螢幕上那個編號不代表任何意義。**不報錯的那種更危險。**
   規則：SELECT 後面只能放 GROUP BY 的欄位，以及聚合函數。
2. **聚合條件寫進 WHERE**，得到 `#1111 - Invalid use of group function`。改用 HAVING。
3. **COUNT(\*) 與 COUNT(欄位) 當成同一件事**。`COUNT(*)` 數列數，`COUNT(欄位)` 會跳過空值 NULL。
   你的 ships 沒有 NULL，所以今天在自己資料上看不出差別；這個差別在今天上機腳本
   步驟 4 的教師前台示範裡會看到。
